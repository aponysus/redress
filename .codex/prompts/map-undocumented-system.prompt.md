# Map an undocumented system

Use Systems Investigator or ordinary Agent mode. Establish the supplied target
repository and bounded subsystem/area; ask for the target if unclear. Confirm
source access through reading/search tools and read applicable instructions and
existing docs. Identify the source revision and relevant uncommitted changes.

Use `source-behavior-documentation` when available, with `repository-onboarding`
for navigation and `legacy-contract-analysis` for calculation or SQL provenance
where useful. Do not claim skill loading without reading it or client evidence.

Perform source-only reconnaissance: map responsibilities, entry points,
execution lifecycle, domain/data boundaries, persistence, external authority,
configuration, and relevant tests. Cite source paths and symbols. Separate
source-confirmed statements, narrow inferences, and unknowns; do not invent
formulas or infer deployed behavior from source alone.

Return a concise map and an ordered set of deeper investigations in chat or
approved scratch storage. Do not write permanent documentation by default or
modify source or project instructions. End with a suggested first vertical
slice, why it matters, and the evidence that would settle its main unknowns.
