# Document a subsystem

Use Documentation or ordinary Agent mode. Establish the selected subsystem or
vertical slice and allowed documentation path from the request; ask for missing
scope before writing. Read applicable project instructions and existing docs.
Use `source-behavior-documentation` if available and actually read or loaded.

Treat prior investigation as navigation, not unquestioned authority. Verify
consequential claims in source at an identified revision. Write or update a
coherent, navigable set of Markdown pages using existing documentation/site
conventions. Explain entry points, execution/data flow, dependencies, the source
of business rules, established calculations, relevant operations, and unknowns.
Distinguish retrieved values from calculated values; never invent missing
stored-procedure logic or undocumented runtime observations.

Use repository-relative source paths and symbols for non-obvious claims,
relative document links, and small grounded diagrams when helpful. Do not rely
on line numbers alone. Separate source-confirmed, inferred, runtime-confirmed,
and unresolved statements where material; runtime-confirmed requires actual
run evidence. Keep sensitive findings only in the authorized target location.

Write only within the allowed documentation scope. Keep temporary notes outside
the repository unless requested; do not change production code or `../../AGENTS.md`.
Report the pages changed, checks actually performed, and the important areas
needing independent source review or controlled runtime characterization.
