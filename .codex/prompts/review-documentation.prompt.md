# Review documentation

Use Documentation Reviewer or ordinary Agent mode. Read applicable project
instructions. Use the supplied documentation scope and primary audience; ask for
them only when unclear. Prefer a fresh context and disclose independence limits.
Use `documentation-quality-review` when present and actually read or loaded.

Perform a bounded, read-only review of the current pages/site. Attempt 2–5 realistic
reader questions spanning understanding, finding information, and completing a task
using documentation only; admit unsupported answers. Use `diagram-review` or
`rendered-docs-review` only when relevant and available. Never fabricate rendering,
skill loading, or tool access. Source correctness is a separate review that may be
requested independently for consequential claims; inspect source only if authorized.

Return a concise reader/scope verdict, task outcomes, and a handful of material
findings ordered by impact. Include precise locations, evidence, reader consequences,
small fixes, confidence, and verification limits. Say when no material issues were
found. Distinguish checks performed from recommendations. Make no file changes or
persistent report; revisions require an explicitly authorized subsequent pass.
Read-only instructions are behavioral constraints, not a sandbox.
